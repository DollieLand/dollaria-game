# DOLLARIA — Winter Wonderland

Новогодняя игра для Telegram (Telegram Mini App): игрок разгадывает слова, получает подарочные билеты, открывает подарки в бутике и собирает коллекцию кукол. Самая ценная коллекция к 31 декабря 2026 года получает главный приз.

Всё бесплатно: в игре нет покупок, энергии и ограничения попыток.

## Что было проверено

- Сервер запускался с настоящей базой PostgreSQL. Пройдены: вход, уровни, подсказки, доп. слова, открытие подарков, дубликаты, календарь, задания, рейтинг, профиль.
- Автотесты (`npm test` в папке backend): проверка подписи Telegram и 300 сгенерированных уровней — все проходят.
- Повтор одной и той же награды невозможен; 8 одновременных нажатий «Открыть подарок» при 3 билетах дали ровно 3 открытия.
- Визуальная часть собирается (`npm run build`), экраны проверены в браузере в размере телефона, свайп по буквам работает мышью.

**Не проверялось:** запуск внутри настоящего Telegram на телефоне и размещение на Render — это первое, что нужно посмотреть после публикации.

## Что нужно сделать вам перед запуском

1. **Картинки кукол.** Положите их в `frontend/public/assets/dolls/`. Точные имена файлов — в `frontend/public/assets/dolls/README.md`. Пока картинки нет, показывается заглушка.
2. **Имена и описания кукол** — в `backend/src/data/dolls.js` (сейчас там временные).
3. **Правила конкурса** — в `frontend/src/data/rules.js`. Заполните всё в квадратных скобках: время окончания, магазин, призы, как будет выдан приз.
4. **Порядок мест при равных очках.** Сейчас: больше уникальных кукол → выше; если и это равно — кто набрал результат раньше. Если нужно иначе — скажите, поменяю.

Награды, цены подсказок и задания меняются в `backend/src/data/economy.js`, `missions.js`, `calendar.js` — без правки остального кода.

## Пошаговый запуск

### Шаг 1. Создайте бота
1. В Telegram откройте **@BotFather** → команда `/newbot` → придумайте имя и адрес бота.
2. BotFather пришлёт **токен** вида `123456789:AA...`. Это пароль бота — никому не показывайте и не вставляйте в код.
3. Аватар бота: `/setuserpic` → загрузите `frontend/public/assets/icons/app-icon-512.png`.
4. Картинка описания: `/mybots` → ваш бот → Edit Bot → Edit Description Picture → `frontend/public/assets/backgrounds/bot-cover-640x360.png`.

### Шаг 2. Загрузите проект в GitHub
1. Зарегистрируйтесь на github.com → кнопка **New repository** → имя `dollaria-game` → **Private** → Create.
2. На странице репозитория нажмите **uploading an existing file** и перетащите туда **содержимое** распакованной папки `dollaria-game` (папки `frontend`, `backend` и файлы README, .gitignore, .env.example).
3. Внизу нажмите **Commit changes**.

> Папок `node_modules` и файлов `.env` в архиве нет — так и должно быть.
> Если файл `.gitignore` не виден (на Mac он скрыт) — нажмите Cmd+Shift+. в Finder.

### Шаг 3. База данных на Render
1. Зарегистрируйтесь на render.com (можно через GitHub).
2. **New → Postgres** → имя `dollaria-db` → регион Frankfurt → Create.
3. Когда база создана, на её странице найдите **Internal Database URL** и скопируйте — понадобится на шаге 4.

### Шаг 4. Сервер (Web Service)
1. **New → Web Service** → выберите репозиторий `dollaria-game`.
2. Заполните:
   - **Root Directory:** `backend`
   - **Build Command:** `npm install`
   - **Start Command:** `npm start`
   - **Region:** тот же, что у базы (Frankfurt)
3. В разделе **Environment Variables** добавьте (подробно — в таблице ниже):
   `DATABASE_URL`, `BOT_TOKEN`, `NODE_ENV=production`, `DATABASE_SSL=true`, `GAME_TIMEZONE=Europe/Moscow`, `CONTEST_END=2026-12-31T23:59:59+03:00`, `TELEGRAM_WEBHOOK_SECRET`.
   `WEBAPP_URL`, `FRONTEND_URL`, `BACKEND_URL` заполните после шага 5.
4. Create. Когда появится «Live», откройте `https://ВАШ-СЕРВЕР.onrender.com/health` — должно быть `{"status":"ok","database":"ok"}`.

### Шаг 5. Визуальная часть (Static Site)
1. **New → Static Site** → тот же репозиторий.
2. Заполните:
   - **Root Directory:** `frontend`
   - **Build Command:** `npm install && npm run build`
   - **Publish Directory:** `dist`
3. Environment Variables: `VITE_API_URL` = адрес сервера из шага 4, например `https://dollaria-api.onrender.com` (без `/` в конце).
4. Create. Получите адрес игры, например `https://dollaria.onrender.com`.

### Шаг 6. Свяжите всё вместе
1. Вернитесь в сервер (шаг 4) → Environment → добавьте:
   - `WEBAPP_URL` = адрес игры из шага 5
   - `FRONTEND_URL` = тот же адрес игры
   - `BACKEND_URL` = адрес сервера
   Сохраните — сервер перезапустится.
2. На странице сервера откройте вкладку **Shell** и выполните:
   ```
   npm run setup-bot
   ```
   Должны появиться строки «готово». Это подключит кнопку «Играть», команду /start и приём сообщений боту.
3. Откройте бота в Telegram → `/start` → **Играть**. Готово!

> Если вкладки Shell нет в бесплатном тарифе: в BotFather `/mybots` → Bot Settings → Menu Button → укажите адрес игры. Кнопка «Играть» заработает, а ответ на /start — после выполнения команды любым способом (её можно запустить и на своём компьютере, см. ниже).

## Переменные окружения сервера

| Переменная | Что это | Где взять |
|---|---|---|
| `DATABASE_URL` | адрес базы | Render → база → Internal Database URL |
| `BOT_TOKEN` | пароль бота | @BotFather |
| `WEBAPP_URL` | адрес игры | Render → Static Site |
| `FRONTEND_URL` | откуда разрешены запросы | тот же адрес игры |
| `BACKEND_URL` | адрес сервера | Render → Web Service |
| `TELEGRAM_WEBHOOK_SECRET` | секрет для сообщений бота | придумайте 30+ латинских букв и цифр |
| `NODE_ENV` | режим работы | `production` |
| `DATABASE_SSL` | шифрование связи с базой | `true` |
| `GAME_TIMEZONE` | часовой пояс игры | `Europe/Moscow` |
| `CONTEST_END` | конец конкурса | `2026-12-31T23:59:59+03:00` (поменяйте время) |

Визуальной части нужна одна переменная: `VITE_API_URL` — адрес сервера.

**Секреты** (`BOT_TOKEN`, `DATABASE_URL`) хранятся только в настройках Render. В коде и в GitHub их нет.

## Безопасность — что уже сделано

- Личность игрока проверяется на сервере по подписи Telegram (initData). Данные из браузера на веру не принимаются.
- Все начисления, шансы гачи, очки и рейтинг считает сервер. Ответы на уровни не отправляются в браузер.
- Каждая награда записывается в журнал с уникальным ключом — дважды её получить нельзя. Баланс не может уйти в минус.
- Повторный запрос открытия подарка (плохая связь) не списывает второй билет.
- Ограничение частоты запросов, проверка всех входных данных, запросы только с адреса игры.
- Вход без Telegram (`DEV_AUTH`) работает только на вашем компьютере и автоматически выключен в продакшене.

## Как устроена игра

- **Уровни** создаёт генератор из словаря (`backend/src/data/dictionary.js`, ~740 слов). Уровень N одинаковый у всех игроков, уровни бесконечны и постепенно усложняются (длиннее слова, больше слов). Добавьте слова в словарь — уровни станут разнообразнее.
- **Награды:** уровень +10 снежинок, каждый 3-й уровень +1 билет, доп. слово +2 снежинки, вход раз в день +20 снежинок.
- **Подарки:** 1 билет = 1 кукла из коллекции недели. Повтор → ленты. 15 лент → 1 билет.
- **Очки:** обычная 10, редкая 20, особая 35, легендарная 60; полный набор +50. Повторы очков не дают.
- **Календарь:** 1–31 декабря, подарок только в свой день, пропуск не сбрасывает остальное. 31 декабря — особая кукла.
- **Коллекции недели** меняются по датам в `backend/src/data/dolls.js`; недельные задания обновляются вместе с ними.

## Запуск на своём компьютере (необязательно)

Нужны Node.js 20+ и PostgreSQL.

```
cd backend
cp .env.example .env      # впишите DATABASE_URL, NODE_ENV=development, DATABASE_SSL=false, DEV_AUTH=true
npm install
npm start                 # сервер на http://localhost:3000
npm test                  # автотесты

cd ../frontend
cp .env.example .env      # VITE_API_URL=http://localhost:3000 и VITE_DEV_USER=1001
npm install
npm run dev               # игра на http://localhost:5173
```

Чтобы проверить календарь до декабря, добавьте в `backend/.env`: `GAME_DATE_OVERRIDE=2026-12-12T12:00:00+03:00` (работает только не в продакшене).

## Если что-то не работает

- **«Откройте игру через Telegram-бота»** — игра открыта в обычном браузере, а не кнопкой «Играть»; или на сервере неверный `BOT_TOKEN`.
- **«Нет связи с сервером»** — проверьте `VITE_API_URL` у Static Site и `FRONTEND_URL` у сервера (адреса без `/` в конце). После изменения `VITE_API_URL` нажмите Manual Deploy у Static Site.
- **Сервер долго просыпается** — на бесплатном тарифе Render сервер засыпает после 15 минут без игроков, первый вход занимает до минуты. Для конкурса лучше платный тариф.
- **/health показывает database: unavailable** — проверьте `DATABASE_URL` и что база и сервер в одном регионе.
